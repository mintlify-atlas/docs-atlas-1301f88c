title: "AgentCore quickstart: install and run your first graph"
description: "Install AgentCore, define a StateGraph, compile it, and invoke your first graph — then explore streaming events, run metadata, and pause and resume."
---

AgentCore gives you a `StateGraph`-style Python API backed by a native C++20 execution kernel. You describe a workflow as nodes and edges, nodes return state patches, and the runtime commits those patches deterministically — handling routing, checkpointing, streaming, and persistent subgraph sessions from the same execution path. This guide walks you from installation through your first running graph, then shows how to stream events and inspect run metadata.

<Steps>
  <Step title="Install AgentCore">
    The published package is `agentcore-graph` on PyPI. The import package inside your code is `agentcore`.

    <CodeGroup>

    ```bash pip
    python3 -m pip install agentcore-graph
    ```

    ```bash with OpenTelemetry
    python3 -m pip install "agentcore-graph[otel]"
    ```

    ```bash with Neo4j graph store
    python3 -m pip install "agentcore-graph[neo4j]"
    ```

    </CodeGroup>

    Verify the install by importing `StateGraph`:

    ```bash
    python3 -c "from agentcore.graph import StateGraph; print('ok')"
    ```

    <Note>
      Published wheels currently target Linux `x86_64` for CPython 3.9 through 3.12. Source builds are available from the repository for other environments.
    </Note>

    The package also installs three MCP helper commands you can use after installation:

    ```bash
    agentcore-mcp --help
    agentcore-mcp-server --help
    agentcore-mcp-config --help
    ```
  </Step>

  <Step title="Define a minimal StateGraph">
    A graph is built from nodes and edges. Nodes are plain Python functions that receive the current state and return a mapping of updates — not mutations of shared state, but a patch that the runtime commits at a single point.

    This example increments a counter until the route function decides to stop:

    ```python
    from agentcore.graph import END, START, StateGraph


    def step(state, config):
        next_count = int(state.get("count", 0)) + 1
        return {"count": next_count}


    def route(state, config):
        return END if state["count"] >= 3 else "step"


    graph = StateGraph(dict, name="counter", worker_count=2)
    graph.add_node("step", step)
    graph.add_edge(START, "step")
    graph.add_conditional_edges("step", route, {END: END, "step": "step"})
    ```

    The key pieces:

    - `StateGraph(dict, name=..., worker_count=...)` defines the graph and native worker parallelism.
    - `add_node(...)` registers a node callback. Callbacks can be synchronous or async.
    - `add_edge(...)` and `add_conditional_edges(...)` describe routing.
    - Node callbacks may accept `state`, `(state, config)`, or `(state, config, runtime)`.

    <Tip>
      Returning a partial mapping (`{"count": next_count}`) instead of a full state copy is the expected pattern. The runtime merges that patch into the committed state snapshot — this is what makes checkpointing, replay, and streaming consistent with state mutation.
    </Tip>
  </Step>

  <Step title="Compile and invoke">
    Once the graph structure is defined, compile it into the native runtime and call `invoke`:

    ```python
    compiled = graph.compile()
    final_state = compiled.invoke({"count": 0})
    print(final_state["count"])  # 3
    ```

    `compile()` lowers the graph definition into native runtime metadata. `invoke(...)` executes one run and returns the final state mapping.

    If a node is deterministic for a declared subset of state keys, you can opt into native memoization at graph-build time:

    ```python
    graph.add_node(
        "score",
        score_candidate,
        deterministic=True,
        read_keys=["candidate_id", "rubric_version"],
        cache_size=32,
    )
    ```

    The cache lives in the native runtime and is invalidated when any declared `read_keys` field changes.
  </Step>

  <Step title="Stream events">
    The same compiled graph can yield public execution events as the run progresses. Today the Python stream surface supports `stream_mode="events"`:

    ```python
    events = list(compiled.stream({"count": 0}))
    for event in events:
        print(event)
    ```

    For async code, use `astream(...)`:

    ```python
    async def run_stream():
        async for event in compiled.astream({"count": 0}):
            print(event)
    ```

    Each event carries node name, step metadata, and — when a persistent subgraph session is in use — `session_id`, `session_revision`, and `namespaces`.

    <Note>
      Stream events are derived from runtime trace data, not a separate event pipeline. That keeps the observable surface aligned with the execution record.
    </Note>
  </Step>

  <Step title="Inspect run metadata">
    Use `invoke_with_metadata(...)` to get the final state along with a summary, trace events, proof digest, and context metadata in one call:

    ```python
    details = compiled.invoke_with_metadata({"count": 0})

    # Final state
    print(details["state"]["count"])        # 3

    # Run summary and checkpoint id
    print(details["summary"]["checkpoint_id"])

    # Trace events (one per step)
    for event in details["trace"]:
        print(event["node_name"], event["step"])
    ```

    `invoke_with_metadata(...)` returns the same final state as `invoke(...)` plus structured run metadata, making it useful for debugging, auditing, and replay validation.

    To add OpenTelemetry spans and metrics, pass an observer:

    ```python
    from agentcore.observability import OpenTelemetryObserver

    observer = OpenTelemetryObserver()
    details = compiled.invoke_with_metadata({"count": 0}, telemetry=observer)
    ```

    Pass `telemetry=True` as shorthand for a default observer when you want spans without constructing one explicitly.
  </Step>
</Steps>

## Use message state

Agent-style message history uses `MessagesState` or an `Annotated[..., add_messages]` field. At join barriers, this compiles to a native message merge: messages with matching non-empty `id` values replace the existing record in place, while messages without ids append.

```python
from agentcore.graph import START, MessagesState, StateGraph


class AgentState(MessagesState, total=False):
    summary: str


graph = StateGraph(AgentState, name="agent", worker_count=4)
graph.add_fanout("fanout")
graph.add_node("draft", lambda state, config: {
    "messages": [{"id": "draft", "role": "assistant", "content": "draft answer"}],
})
graph.add_node("revise", lambda state, config: {
    "messages": [{"id": "draft", "role": "assistant", "content": "revised answer"}],
})
graph.add_join("join", lambda state, config: {
    "summary": state["messages"][-1]["content"],
})
graph.add_edge(START, "fanout")
graph.add_edge("fanout", "draft")
graph.add_edge("fanout", "revise")
graph.add_edge(["draft", "revise"], "join")
graph.set_finish_point("join")
```

`MessagesState` exports `messages: Annotated[list[dict], add_messages]`. The `add_messages` reducer merges by `id`, which avoids duplicating messages when branches converge.

## Pause and resume

Nodes can intentionally pause a run using `Command(wait=True)`. The runtime saves a resumable checkpoint, and you can restore it by checkpoint id:

```python
from agentcore.graph import Command


def specialist(state, config):
    if not state.get("ready", False):
        return Command(update={"ready": True}, wait=True)
    return {"done": True}


compiled = graph.compile()
paused = compiled.invoke_until_pause_with_metadata({"ready": False})
resumed = compiled.resume_with_metadata(paused["summary"]["checkpoint_id"])
```

This is the building block for human-in-the-loop steps and external wait points.
