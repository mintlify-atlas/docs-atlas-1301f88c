AgentCore integrates with the Model Context Protocol (MCP) as an interoperability layer. Remote tools, prompts, and resources can cross a process boundary over `stdio` while the graph runtime continues to own state patches, scheduling, checkpoints, traces, and replay. You can consume tools from any MCP server inside a graph, talk to the full MCP protocol surface directly, or expose AgentCore as an MCP server for Claude, Codex, Gemini, or any other MCP-compatible client.

## Which path to use

| Goal | Use |
|---|---|
| Call tools from an MCP server inside a graph | `compiled.tools.register_mcp_stdio(...)` |
| Access prompts, resources, completions, or subscriptions directly | `StdioMCPClient` |
| Expose AgentCore tools or graphs to an MCP client | `MCPServer` + `agentcore-mcp-server` |
| Generate ready-to-paste client config | `agentcore-mcp-config` |

## Connect a graph to an MCP tool server

`compiled.tools.register_mcp_stdio(...)` imports tools from an external MCP server into a compiled graph's tool registry. After registration, graph nodes call them with `runtime.invoke_tool(...)` exactly as they would any native tool.

<Steps>
  <Step title="Build and compile your graph">
    Define a node that calls a remote tool by name, then compile the graph normally.

    ```python
    import sys
    from agentcore.graph import END, START, StateGraph


    def use_remote_tool(state, config, runtime):
        result = runtime.invoke_tool(
            "remote_upper",
            {"text": state["text"]},
            decode="json",
        )
        return {"upper": result["upper"]}


    graph = StateGraph(dict, name="mcp_client_demo", worker_count=2)
    graph.add_node("use_remote_tool", use_remote_tool, kind="tool")
    graph.add_edge(START, "use_remote_tool")
    graph.add_edge("use_remote_tool", END)

    compiled = graph.compile()
    ```
  </Step>

  <Step title="Register the MCP server">
    Point `register_mcp_stdio` at the command that starts the MCP server process. The `prefix=` argument namespaces imported tool names so they do not collide with local tools.

    ```python
    compiled.tools.register_mcp_stdio(
        [sys.executable, "./my_mcp_server.py"],
        prefix="remote",
    )
    ```

    Supported options:

    | Option | Purpose |
    |---|---|
    | `prefix=` | Namespace imported tool names locally |
    | `include=` / `exclude=` | Filter which remote tools are mirrored |
    | `env=` / `cwd=` | Control child process launch context |
    | `startup_timeout=` | MCP handshake timeout (default `10.0` s) |
    | `request_timeout=` | Per-request timeout (default `30.0` s) |
    | `tool_timeout=` | Per-call timeout for mirrored tools |
    | `result_mode="auto"\|"raw"` | Normalize results or return raw MCP envelopes |
    | `argument_key=` | Wrap non-mapping requests into `{argument_key: request}` |
  </Step>

  <Step title="Invoke the graph">
    ```python
    result = compiled.invoke({"text": "hello"})
    ```

    The node calls `runtime.invoke_tool("remote_upper", ...)` and receives the normalized result. The MCP process boundary is invisible to the node.
  </Step>
</Steps>

## Use StdioMCPClient directly

`StdioMCPClient` gives you the full MCP protocol surface without routing through a graph tool registry. Use it when you need prompts, resources, completions, subscriptions, or sampling outside of graph nodes.

```python
import sys
from agentcore.mcp import StdioMCPClient


with StdioMCPClient([sys.executable, "./my_mcp_server.py"]) as client:
    tools = client.list_tools()
    prompts = client.list_prompts()
    resources = client.list_resources()

    tool_result = client.call_tool("upper", {"text": "hello"})

    prompt = client.get_prompt(
        "review_code",
        {
            "language": "python",
            "repository": "agentcore",
            "question": "How should we wire MCP?",
        },
    )
    guide = client.read_resource("memo://guide/overview")
```

`get_prompt(...)` returns a `RenderedMCPPrompt`, which can be passed directly to model invocation or flattened:

```python
rendered = client.get_prompt(
    "investigate_topic",
    {"topic": "scheduler", "question": "What should we inspect?"},
)

text_payload = rendered.to_model_input()
message_payload = rendered.to_model_input(mode="messages")
```

### Constructor

```python
StdioMCPClient(
    command,
    *,
    cwd=None,
    env=None,
    startup_timeout=10.0,
    request_timeout=30.0,
    client_name="agentcore",
    client_version="0.1",
    roots=None,
    roots_list_changed=True,
    sampling_handler=None,
    elicitation_handler=None,
    log_handler=None,
    notification_handler=None,
)
```

Optional capabilities are declared at construction time and advertised during `initialize`. This matches MCP capability negotiation and keeps the per-call surface uniform.

```python
from agentcore.mcp import StdioMCPClient


def sampling_handler(request, client):
    last_text = ""
    for message in request["messages"]:
        content = message["content"]
        if content["type"] == "text":
            last_text = str(content.get("text", ""))
    return {
        "role": "assistant",
        "content": {"type": "text", "text": f"sample::{last_text}"},
        "model": "fixture-sampler",
        "stopReason": "endTurn",
    }


def elicitation_handler(request, client):
    return {
        "action": "accept",
        "content": {"reviewer": "agentcore", "approved": True},
    }


with StdioMCPClient(
    [sys.executable, "./my_mcp_server.py"],
    roots=["file:///workspace/agentcore"],
    sampling_handler=sampling_handler,
    elicitation_handler=elicitation_handler,
) as client:
    client.set_logging_level("warning")
    client.subscribe_resource("memo://guide/overview")
```

### Available methods

- `start()` — connect and complete MCP `initialize`
- `list_tools()` / `call_tool(name, arguments)` / `call_tool_raw(...)`
- `list_prompts()` / `get_prompt(name, arguments)` / `get_prompt_raw(...)`
- `list_resources()` / `list_resource_templates()` / `read_resource(uri)` / `read_resource_raw(...)`
- `complete(ref, argument_name, value)` / `complete_prompt_argument(...)` / `complete_resource_argument(...)`
- `subscribe_resource(uri)` / `unsubscribe_resource(uri)`
- `set_roots(roots)` / `list_roots()`
- `set_sampling_handler(handler)` / `set_elicitation_handler(handler)`
- `set_log_handler(handler)` / `set_notification_handler(handler)`
- `set_logging_level(level)`
- `drain_notifications()` / `drain_logs()` / `drain_resource_updates()`
- `close()`

## Expose AgentCore as an MCP server

`MCPServer` lets any MCP-compatible client call your AgentCore tools, prompts, and resources over `stdio`.

### Constructor

```python
MCPServer(
    *,
    name="agentcore-mcp",
    version="0.1",
    instructions="",
    request_timeout=30.0,
    enable_logging=True,
    resource_subscriptions_enabled=True,
    list_changed_notifications_enabled=True,
    auto_notify_catalog_changes=True,
)
```

### Register tools, prompts, and resources

```python
from agentcore import ChatPromptTemplate
from agentcore.mcp import MCPServer


server = MCPServer(name="agentcore-fixture", version="0.1")


@server.tool("upper")
def upper(arguments):
    return {"upper": str(arguments["text"]).upper()}


server.add_prompt_template(
    "review_code",
    ChatPromptTemplate.from_messages(
        [
            ("system", "You are reviewing {language} code."),
            ("user", "Question: {question}"),
        ]
    ),
    arguments=[
        {"name": "language", "required": True},
        {"name": "question", "required": True},
    ],
)


server.add_resource(
    "memo://guide/overview",
    {"text": '{"project":"agentcore"}', "mimeType": "application/json"},
)


@server.resource_template("memo://guide/{topic}")
def guide(arguments):
    return {"text": f"Guide for {arguments['topic']}"}


server.run_stdio()
```

### Reuse a compiled graph's tool registry

`MCPServer.from_compiled_graph(...)` wraps an existing compiled graph so external callers hit the same tool registry that graph nodes use through `runtime.invoke_tool(...)`.

```python
from agentcore.mcp import MCPServer


server = MCPServer.from_compiled_graph(compiled, name="agentcore-tools")
server.run_stdio()
```

### Access client-facing MCP features from a handler

When a handler accepts `metadata`, AgentCore injects the active session under `metadata["session"]` and `metadata["mcp"]`. The session object exposes `list_roots()`, `sample(...)`, `elicit(...)`, and `send_log(...)`.

```python
@server.tool("optional_context")
def optional_context(arguments, metadata):
    session = metadata["mcp"]
    roots = session.list_roots()
    sampled = session.sample(
        [{"role": "user", "content": {"type": "text", "text": "Summarize this repo."}}],
        system_prompt="Keep it brief.",
        max_tokens=64,
    )
    elicited = session.elicit(
        "Provide reviewer context.",
        {
            "type": "object",
            "properties": {"reviewer": {"type": "string"}},
            "required": ["reviewer"],
            "additionalProperties": False,
        },
    )
    session.send_log("warning", {"root_count": len(roots)}, logger="agentcore.mcp")
    return {"roots": roots, "sampled": sampled, "elicited": elicited}
```

## Installed CLI commands

Installing `agentcore-graph` adds three commands:

- **`agentcore-mcp`** — general entrypoint
- **`agentcore-mcp-server`** — launch an MCP server from a target reference
- **`agentcore-mcp-config`** — print ready-to-paste client configuration

The module entrypoint is also available:

```bash
python -m agentcore.mcp serve --target package.module:build_server
python -m agentcore.mcp config codex --name local-agentcore --target package.module:build_server
```

Accepted target forms:

- `package.module:server`
- `package.module:build_server`
- `./local_server.py:server`
- `./local_server.py:create_server`

If the target resolves to a `StateGraph`, `CompiledStateGraph`, or a tool registry, the launcher wraps it through `MCPServer.from_compiled_graph(...)` or `MCPServer.from_tool_registry(...)` automatically.

## Generate client configuration

`agentcore-mcp-config` prints configuration snippets for Claude, Codex, and Gemini using the current Python interpreter path. This makes output safe for virtual environments and packaged installs.

<Tabs>
  <Tab title="Claude">
    ```bash
    agentcore-mcp-config claude --name local-agentcore --target ./my_server.py:build_server
    ```

    Prints:
    - A `claude mcp add-json ...` command you can run directly
    - A `.mcp.json` snippet for project-scoped config
    - A `claude_desktop_config.json`-style block for Claude Desktop

    The generated server command uses `python -m agentcore.mcp serve --target ...` rather than the console script name so it works reliably inside any virtual environment.
  </Tab>
  <Tab title="Codex">
    ```bash
    agentcore-mcp-config codex --name local-agentcore --target ./my_server.py:build_server
    ```

    Prints:
    - A `codex mcp add ...` command
    - A `~/.codex/config.toml` snippet
  </Tab>
  <Tab title="Gemini">
    ```bash
    agentcore-mcp-config gemini --name local-agentcore --target ./my_server.py:build_server
    ```

    Prints:
    - A `gemini mcp add ...` command
    - A `settings.json` snippet
  </Tab>
</Tabs>
